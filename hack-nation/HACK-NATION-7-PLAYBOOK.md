## D. What Hack-Nation optimizes for (research)

### Challenge tracks (organiser model)

Tracks are **sponsor-defined real problems**, not “build anything”:

- Problem statement + **APIs / data / tools**
- **Evaluation criteria** (per track)
- Prizes + optional follow-on (Venture Lab)

Typical domains (historical): agents, voice, healthcare, multimodal, robotics, trust/safety, climate, enterprise.

**Edition 7:** expect **~6–8 tracks**; exact titles drop at kickoff on HackOS.

### Hackathon 6 benchmark (Jul 2026 — use as pattern, not guarantee for #7)

- **~5,500 applicants → ~2,000 builders**, **$35K+** pool, **6 challenge tracks**, top 3 per track + **overall winner** (team **AMBR**).
- **Track examples + sponsors:** Negotiator (ElevenLabs), VC Brain, RealDoor/RealPage, Data Legend (Databricks), Women’s hormonal health, Genome Firewall / AMR.
- **Winning pattern:** narrow scope, **working demo**, sponsor APIs used correctly, credible domain story, small strong teams (often 3–4) — but **solo podiums happen**.

### Venture Lab (<1% of applicants)

~**29–30 teams** from ~**6,500** applicants cited in organiser posts. Selection emphasizes:

- **Execution** (shipped prototype, not slides)
- **Technical depth**
- **Clarity of vision** (problem → user → why AI)
- Traction narrative helps post-hackathon (GRIT example: top 3 at hack → Venture Lab)

### Judging (official + inferred)

- **Official:** Jury decides per **rules published for the event**; no guaranteed score (HackOS AGB §8).
- **Devpost (5th India edition):** only listed criterion “Energy” — **not authoritative for #7**.
- **5th online edition (secondary source):** finalist **~2 min pitches**; top teams after jury cut.
- **Inferred winners’ traits:** live product, sponsor alignment, verifiable outputs (citations, evals), demo polish, team can explain **tradeoffs**.

### 2. First 60 minutes after kickoff (critical)

1. Read **all** challenge briefs + **evaluation criteria** + sponsor APIs.
2. Score each track (1–5) on: **fit to your stack**, **API credit advantage**, **scope fit in 20h**, **judge-visible demo**.
3. **Pick one track** — avoid “platform for everything.”
4. Assign roles: **demo path owner**, **deploy owner**, **video owner** (can overlap).
5. **Claim mentor office hours** in HackOS as soon as Mentors unlock.
6. Redeem **Credits & Codes** immediately; note expiry and rate limits.

**Track selection heuristic**

```
Score = 0.35*PersonalFit + 0.25*SponsorTooling + 0.25*DemoClarity + 0.15*Uniqueness
```

Pick highest score where you can show a **non-technical judge** value in **30 seconds**.

### 3. Build scope (what wins in 24h)

**Do**

- One **hero user journey** (3–5 screens or one CLI + one UI).
- **Real data** (even small curated set) beats synthetic-only.
- **Sponsor API** in the critical path (not optional garnish).
- **Evaluation hook:** 3–5 test cases with before/after metrics.
- **README:** problem, approach, how to run, demo link, team.
- **Deploy early** (hour 4–6); rebuild on production URL all weekend.

**Don’t**

- Multi-challenge submissions, microservices maze, training large models from scratch.
- Slide-only or video-only without working URL.
- Ignore track rubric keywords in README and demo script.
