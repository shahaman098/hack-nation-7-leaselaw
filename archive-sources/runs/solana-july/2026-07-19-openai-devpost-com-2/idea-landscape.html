TracePatch Verifier

Before: the submission checklist shows 7 of 12 requirements verified, a README command that fails, and a demo script that claims GPT-5.6 usage without a matching trace. After: the UI applies one correction patch, reruns the setup command, shows 12 of 12 requirements verified, and displays the accepted README diff tied to src-007ffb1ef031 and https://openai.devpost.com/rules.

User
Parent concept-004 mutation. Hackathon builders and repo maintainers preparing a judge-testable submission who need verified corrections committed into their README, demo script, and setup workflow before deadline. Evidence: src-007ffb1ef031 maps to https://openai.devpost.com/rules. Data access: verified.
Mechanism
m1_constraint_backed_decision_diff: a requirement-to-artifact consistency checker that converts official submission rules and repository evidence into constraints, detects mismatches, and proposes the smallest verified correction to the workflow documentation or demo script.
Action

The visible state change is a requirement row moving from 'unsupported' to 'corrected' with the exact file diff, source URL, and evidence ID attached.

Minute 2: GPT-5.6 maps official rule clauses to repo evidence while Codex-built tests reproduce the failing setup step. FairQueue Diff: Constraint-Safe Allocation Committer

The demo loads a scarce-resource queue, attempts to approve an allocation, shows a blocked commit due to two rule conflicts, then applies a corrected invariant set and visibly changes applicant statuses from proposed to committed with an audit ledger.

User
Small organizations, community operators, and internal operations teams allocating limited funds, slots, grants, equipment, or staff time under written rules.
Mechanism
m1_constraint_backed_decision_diff: a decision-state consistency checker from formal methods and policy verification, adapted to compare written allocation rules, structured applicant/resource data, edge cases, and proposed decisions before writeback.
Action
Commits an allocation decision packet: approved/held/rejected statuses, a signed rationale ledger, exception queue, minimal counterexample report, and an exportable CSV/API payload that downstream operations can use as the source of action.
Demo
Seed a food-bank delivery or equipment-loan scenario with 30 cases, 12 available slots, one hidden eligibility contradiction, and one priority tie. FairQueue Diff finds the minimal counterexample, shows the exact affected cases, GPT-5.6 explains the policy conflict in operator language, Codex-backed tests prove the corrected decision no longer violates the seeded rules, and the final commit exports the allocation packet.

Backup 2

Rubric Regression Lab

Before: a rubric draft looks acceptable after two manual spot checks. After: the generated regression suite runs 30 learner traces, finds that removing one process-evidence clause changes 7 pass/fail outcomes, opens the failing trace, and blocks release until the rubric change is revised.

User
Curriculum leads and assessment operations staff who maintain shared rubrics across many instructors and need to prevent rubric edits from silently changing learner outcomes. Parent ID: concept-004. Evidence: src-c820642b7f7f at https://openai.devpost.com/details/faqs. Data access: verified.
Mechanism
Perturbation-based robustness evaluator from simulation and experimental design, mutated into generated regression testing: create fixture pairs from historical traces, encode expected invariant and sensitive outcomes, run old and new rubric evaluators, and fail the rubric release when deltas exceed policy thresholds.
Action
The app generates and runs a regression test suite for a proposed rubric release, then writes a release gate result: passed, failed, or needs review. The visible state changes from 'rubric draft' to 'release blocked by regression test R-014' or 'approved with regression receipt'.
Demo
Minute 1: load a rubric draft and click Generate Regression Suite. Minute 2: GPT-5.6 proposes invariant tests and Codex-built runner executes them with a fixed seed. Minute 3: show measurable before/after: manual spot check catches 0 of 7 changed pass/fail outcomes; regression suite catches 7 of 7, blocks release, then passes after the clause is restored.
