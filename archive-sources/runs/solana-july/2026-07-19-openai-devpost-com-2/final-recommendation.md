# Final recommendation: OpenAI Build Week

## Primary concept
**Working title:** TracePatch Verifier
**Internal id:** `mut-r4-01-tracepatch-verifier`
**Primary user:** Parent concept-004 mutation. Hackathon builders and repo maintainers preparing a judge-testable submission who need verified corrections committed into their README, demo script, and setup workflow before deadline. Evidence: src-007ffb1ef031 maps to https://openai.devpost.com/rules. Data access: verified.
**Painful workflow:** A runnable project can still fail submission review because the README, demo narration, setup path, sample data, and required Codex/GPT-5.6 evidence drift from what the repository actually does; teams discover the mismatch only while submitting or when judges cannot reproduce the demo.
**Imported mechanism:** m1_constraint_backed_decision_diff: a requirement-to-artifact consistency checker that converts official submission rules and repository evidence into constraints, detects mismatches, and proposes the smallest verified correction to the workflow documentation or demo script. _(from software supply chain attestation)_
**Data sources:** https://openai.devpost.com/
**Core computation:** TracePatch Verifier ingests the official rules from https://openai.devpost.com/rules, verified as src-007ffb1ef031, plus local README, package scripts, test logs, demo transcript, and Codex session notes. It builds a constraint graph linking each submission requirement to concrete repo evidence, detects unsupported claims or missing setup steps, and generates a patch-ready correction with cited evidence. GPT-5.6 materially translates rules and local traces into evidence-linked requirement checks, classifies claim severity, and drafts the correction text only from verified artifacts. Codex materially builds the repo scanner, rule fixtures, patch generator, deterministic tests, browser review UI, and the audit log showing every generated correction and accepted diff.
**Last-mile action:** The maintainer accepts a verified correction patch into the workflow: README setup steps, demo checklist, sample-data instructions, and Codex/GPT-5.6 contribution notes are changed from unverified prose to evidence-linked text. The visible state change is a requirement row moving from 'unsupported' to 'corrected' with the exact file diff, source URL, and evidence ID attached.
**Visible transformation:** Before: the submission checklist shows 7 of 12 requirements verified, a README command that fails, and a demo script that claims GPT-5.6 usage without a matching trace. After: the UI applies one correction patch, reruns the setup command, shows 12 of 12 requirements verified, and displays the accepted README diff tied to src-007ffb1ef031 and https://openai.devpost.com/rules.
**Killer demo:** Minute 1: load a sample hackathon repo with a stale README and missing demo evidence; baseline checklist leaves five unsupported requirements. Minute 2: GPT-5.6 maps official rule clauses to repo evidence while Codex-built tests reproduce the failing setup step. Minute 3: accept the generated correction patch, rerun verification, and show the README/demo workflow changing from unsupported to verified with before/after counts.
**Hard-to-fake advantage:** Unlike a generic checklist or submission coach, the product performs a durable write into the actual workflow documentation and proves the correction with executable repo checks. Parent concept-004 assessed learner process; this mutation changes user, workflow, mechanism family, data, last-mile action, and demo type toward verified correction writeback.
**Sponsor dependency:** GPT-5.6 reasoning and Codex-built evaluation harness

## Structurally different backup 2
**Rubric Regression Lab** (`mut-r4-04-rubric-regression-lab`)
- User: Curriculum leads and assessment operations staff who maintain shared rubrics across many instructors and need to prevent rubric edits from silently changing learner outcomes. Parent ID: concept-004. Evidence: src-c820642b7f7f at https://openai.devpost.com/details/faqs. Data access: verified.
- Mechanism: Perturbation-based robustness evaluator from simulation and experimental design, mutated into generated regression testing: create fixture pairs from historical traces, encode expected invariant and sensitive outcomes, run old and new rubric evaluators, and fail the rubric release when deltas exceed policy thresholds.
- Demo: Minute 1: load a rubric draft and click Generate Regression Suite. Minute 2: GPT-5.6 proposes invariant tests and Codex-built runner executes them with a fixed seed. Minute 3: show measurable before/after: manual spot check catches 0 of 7 changed pass/fail outcomes; regression suite catches 7 of 7, blocks release, then passes after the clause is restored.
